# 진단 라벨 사전

케이스를 만들 때 쓰는 참조표다. **구현은 일부러 뺐다** — 임계값, 판별 신호, 라벨 사이 우선순위,
어느 슬롯에서 뽑히는지는 여기 없다. 케이스 작성자가 그걸 보고 기대 라벨을 정하면 코드가
자기 자신을 채점하는 꼴이 되기 때문이다.

쓰는 법: 상황을 먼저 정한다 → **이 상황에서 무엇을 고쳐야 하나**를 판단한다 → 그 처방을 가진
라벨이 기대 라벨이다. 코드가 다른 라벨을 내면 둘 중 하나가 틀린 것이고, 그게 이 데이터셋이
찾으려는 것이다.

그룹: A 검색 · B 생성 · C 컨텍스트 구조 · D 데이터(파이프라인으로 못 고침)

---

## A — 검색이 정답 근거를 못 가져왔다

| 라벨 | 상황 | 처방 |
|---|---|---|
| `retrieval_low_rank` | 정답 청크가 후보에는 있는데 순위가 낮아 상위 k개 밖으로 밀렸다 | 리랭커를 켠다 |
| `retrieval_rank_fusion_loss` | 벡터 검색이나 키워드 검색 중 한쪽은 정답을 상위에 뒀는데, 둘을 합치는 과정에서 순위가 깎였다 | 하이브리드 가중치를 유리한 쪽으로 옮긴다 |
| `retrieval_duplicate_crowding` | 거의 같은 내용의 청크들이 상위 자리를 차지해 정답이 밀려났다 | 중복을 접는다(MMR) |
| `retrieval_rerank_candidate_miss` | 정답 청크가 리랭커에 넘어가는 후보 목록에 아예 없어서 리랭커가 보지도 못했다 | 후보 목록을 넓힌다 |
| `retrieval_reranker_demotion` | 리랭커가 정답 청크를 후보로 받고도 아래로 떨어뜨렸다 | 리랭커를 되돌리거나 모델을 바꾼다 |
| `retrieval_reranker_ineffective` | 리랭커가 정답 청크를 봤지만 상위로 끌어올리지 못했다 (떨어뜨린 게 아니라 못 올린 것) | 리랭커 모델을 바꾼다 |
| `retrieval_lexical_mismatch` | 벡터 검색은 놓쳤는데 키워드로는 찾아진다. 표현은 다르지만 단어가 겹치는 경우 | 키워드 검색을 함께 쓴다(하이브리드) |
| `retrieval_semantic_mismatch` | 벡터·키워드 둘 다 못 찾았다. 질문과 근거의 표현이 너무 달라 연결이 안 된다 | 임베딩 모델을 바꾸거나 청킹 전략을 바꾼다 |
| `retrieval_missing_gold` | 정답 청크가 코퍼스에는 있는데 검색 결과에 안 들어왔다. 어느 단계에서 놓쳤는지는 모른다 | 검색 개수를 늘리거나 청크 겹침·크기를 조정한다 |
| `retrieval_incomplete_enumeration` | 답하려면 근거가 여러 개 필요한데 검색 개수가 고정이라 일부만 가져왔다 | 검색 개수를 질문에 따라 늘린다 |
| `retrieval_missing_bridge_dependency` | 2단계 질문인데, 두 번째 단계의 근거는 첫 단계 답을 알아야 찾을 수 있어서 원 질문으로는 안 잡힌다 | 질문을 단계별로 쪼개 검색한다 |
| `chunking_overchunking` | 정답 근거가 청크 하나에 담기기엔 너무 길어서 여러 조각으로 쪼개졌다. 겹침을 늘려도 한 청크에 못 담는다 | 청크 크기를 키운다 |
| `chunking_context_mismatch` | 정답 근거가 청크 경계에 걸쳐 잘렸다. 조각을 합치면 근거가 온전해진다 | 청크 겹침이나 크기를 늘린다 / 문장 경계로 자른다 |
| `chunking_underchunking` | 청크가 근거보다 훨씬 커서 무관한 내용이 잔뜩 딸려온다 | 청크 크기를 줄인다 |
| `reranker_low_precision` | 리랭커가 질문과 무관한 청크를 상위로 올렸다 | 리랭커 모델을 바꾸거나 문턱을 조인다 |

## B — 근거는 있는데 생성이 잘못했다

| 라벨 | 상황 | 처방 |
|---|---|---|
| `generation_hallucination` | 정답 근거를 줬는데도 근거에 없는 내용을 지어냈다 | 온도를 낮추고 인용을 요구한다 / 생성 모델을 올린다 |
| `generation_partial_answer` | 답의 일부만 말하고 나머지 요소를 빠뜨렸다 | 빠짐없이 답하도록 프롬프트를 고친다 |
| `generation_contradiction` | 근거와 정면으로 어긋나는 답을 냈다 | 답을 근거와 대조하는 검증 단계를 넣는다 |
| `generation_misinterpretation` | 질문의 관계나 조건을 잘못 읽었다 | 질문을 다시 진술하게 한다 |
| `generation_numerical_error` | 수치를 잘못 읽거나 잘못 계산했다 | 수치 인용을 요구하고 계산을 검산한다 |
| `generation_hop_binding_error` | 여러 근거를 다 찾았는데 서로 잘못 엮었다 (A의 값을 B에 붙이는 식) | 단계별 근거를 답에 묶어 쓰게 한다 |
| `generation_abstention_failure` | 근거가 없는 질문인데 모른다고 하지 않고 답을 지어냈다 | 근거 없을 때 기권하도록 강화하고 인용을 요구한다 |
| `generation_wrongful_abstention` | 근거가 검색됐는데도 "알 수 없다"고 회피했다 | 기권 조건을 완화한다 |
| `generation_parametric_overreliance` | 답은 맞았는데 검색된 근거에 기대지 않고 모델이 외워둔 지식으로 답했다 | 인용을 요구하고 온도를 낮춘다 |

## C — 근거도 있고 답할 수 있는데, 컨텍스트 구성 때문에 틀렸다

| 라벨 | 상황 | 처방 |
|---|---|---|
| `too_long_context` | 컨텍스트가 너무 길어 모델이 근거를 제대로 못 썼다 | 검색 개수를 줄이거나 컨텍스트를 압축한다 |
| `lost_in_the_middle` | 정답 청크가 컨텍스트 한가운데 묻혀서 참조되지 않았다 | 검색 개수를 줄이거나 정답을 양끝으로 재배치한다 |
| `context_noise_interference` | 정답이 아닌 청크의 상충하는 정보에 끌려가 답이 틀어졌다 | 노이즈를 걸러내거나 압축한다 / 충돌 시 처리를 지시한다 |

## D — 파이프라인 설정으로는 못 고친다

| 라벨 | 상황 | 처방 |
|---|---|---|
| `corpus_gap` | 답에 필요한 문서가 코퍼스에 아예 없다 | 해당 주제 문서를 수집해 인덱싱한다 (사람이) |
| `corpus_gap_partial_hop` | 여러 단계 질문에서 중간 단계를 뒷받침하는 문서가 빠졌다 | 빠진 단계의 문서를 수집한다 (사람이) |
| `bad_gold_answer` | 파이프라인이 아니라 정답셋이 틀렸거나 모호하다 | probe를 다시 만든다 (사람이) |
| `bad_gold_chunk` | 정답 텍스트는 맞는데 근거로 지정된 청크가 엉뚱한 곳을 가리킨다 | 골드 청크를 다시 지정한다 (사람이) |

## 롤업 라벨

구체적인 원인을 하나도 짚지 못했을 때 그룹만 알리고 나오는 라벨이다. 케이스의 기대 라벨로
적을 일은 드물다 — 이게 나왔다는 건 대개 진단이 원인을 못 찾았다는 뜻이다.

`retrieval_failure` · `generation_failure` · `context_failure`

---

## 기대 라벨을 정할 때

- 한 케이스에 라벨이 여럿 나올 수 있다. 검색 실패와 생성 실패가 같이 일어날 수 있고,
  자료 결손(D)은 다른 라벨과 함께 붙는다.
- 처방이 갈리면 라벨도 갈라야 한다. "청크를 키운다"와 "청크를 줄인다"는 반대 처방이라
  같은 상황에 둘 다 맞을 수 없다.
- 판단이 애매하면 케이스에 이유를 적어두고 리뷰에서 정한다. 애매한 케이스일수록
  진단이 실제로 어떻게 가르는지 드러내는 값이 크다.
